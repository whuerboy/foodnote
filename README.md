# 食简 Foodnote

可以实际保存数据的 iPhone-first 个人饮食管理 PWA。内置79项可编辑常用食物参考数据，饮食记录由用户实际添加；不需要账号或服务器。

## 本地运行

需要 Node.js 22.12+。

```sh
npm ci
npm run dev
```

打开终端显示的本地地址。开发模式用于开发，不注册正式离线缓存。测试 PWA：

```sh
npm run build
npm run preview
```

在 `http://localhost:4173` 首次联网打开，等待「已准备好离线使用」，然后可断网重新加载并操作。正式部署上传 `dist/` 到 HTTPS 静态托管，SPA 路径回退到 `index.html`。手机访问局域网 HTTP 开发地址可检查界面，但 Service Worker 需要 HTTPS（localhost 除外）；在 iPhone Safari HTTPS 页面选择「分享 → 添加到主屏幕」。应用内有新版本提示，用户确认后更新。

## 已实现

- React + TypeScript + Vite，Tailwind CSS；采用 shadcn/ui Button 结构（CVA、Radix Slot）及 Radix Dialog，无外部字体或图片请求。
- 米白/鼠尾草绿；完整复用 V4 原型的10个 SVG 食物插画；页面内容标题、底部五位置导航及中央加号；iPhone 安全区和桌面适配。
- 首页日期选择、前后日期按钮及空白区域横向手势；独立固定摄入热量摘要，避免滚动时内容跳动；四个精简餐次卡，点击查看明细；每条记录的实际食用量和营养快照。
- 拍照 / 相册识别中英文营养成分表（Tesseract.js 本机 OCR），核对第一列含量、单位和每份重量后折算每100g/mL，并进入食物编辑保存。缺失值留空，能量单位与标签基准不明时要求确认。
- 能量输入支持 kcal、kJ、J；统一保存 kcal，自动换算并保留历史记录。
- 自适应布局：320px小屏表单单列、统计卡纵排；桌面双列餐次与四列营养汇总。
- 创建、编辑、收藏、归档、恢复和永久删除食物；食物按每100g或100mL标注，明确生重/熟重/干重。
- 组合菜品原料营养累计，以成品实际出品量折算每100单位营养；原料各自保留营养快照，可编辑原料及出品量。
- 菜品、餐次、单条记录左滑露出删除按钮并确认；提供「···」按钮供鼠标/键盘使用。手势与日期浏览区域分离，垂直滚动优先。
- 最近使用、收藏筛选；餐次复制到指定日期/餐次，复制历史快照。
- Dexie IndexedDB 持久化，`useLiveQuery` 联动主页、菜单与统计；无永久模拟业务数据。
- Recharts 周/月/年图表，支持历史统计周期，累计及有记录日期的日均营养。
- 每日营养目标设置；JSON 导出、校验后事务恢复；请求浏览器持久存储。
- PWA manifest、PNG 安装图标、Service Worker 离线缓存和升级提示。
- Vitest 营养/日期/统计/数据库测试，Playwright Chromium/WebKit 手机尺寸及桌面完整流程。

## V4 UI 基线

原型现已提供并保存在 `references/diet_pwa_v4.html`，原文件与参考副本均未改写。`public/food-icons/` 的10个SVG直接提取自该原型，含燕麦、虾仁、西兰花、鸡胸肉、土豆、米饭、牛奶、鸡蛋、香蕉和组合菜品；旧版图标ID兼容映射。

已对照原型的米白/鼠尾草绿色值、字号、日期选择卡、热量卡及三大营养素进度、精简餐次卡/明细弹层、单卡片菜单列表、大插画详情页、周期日均统计及中央加号导航。保留产品必需的收藏/最近/归档筛选和真实备份操作；原型的演示数据与演示说明没有进入正式业务。桌面使用更宽的布局与双列餐次卡，创建/编辑采用支持键盘与焦点管理的 Radix 弹层。与原型相比，这些为真实应用功能作出的适配并非逐像素一致。

## 最小真实流程

1. 菜单 → 底部「＋」→ 手动创建食物 → 新建燕麦，每100g输入热量380、蛋白质13、碳水68、脂肪7，重量基准选择干重。
2. 首页 → 底部「＋」→ 选择燕麦、早餐、50g → 保存。
3. 当日摄入热量增加190kcal，蛋白质6.5g；刷新仍存在；统计自动更新。
4. 编辑燕麦营养只影响新记录，已保存记录保持当时的名称、单位、重量基准和营养数据。
5. 我的 → 导出 JSON，换设备后恢复（恢复会替换当前设备全部食物、记录和目标，操作前有数量提示及确认）。

## 计算约定

食用营养 = 每100单位营养 × 食用量 / 100。配方每100单位营养 = Σ原料营养 / 成品总量 × 100。原料可混合 g 与 mL，由各原料自身营养基准计算，出品量必须实测；不做密度转换或生熟重自动转换。不自动用三大营养素反推包装热量。计算保持精度，仅显示时舍入。配方引用其他菜品时使用其当时的营养值，不递归动态重算，因此不会出现循环配方。删除食品/归档食品不会删除饮食历史。

周从周一开始；月和年按自然日历分组。日期采用设备本地日历日期，避免 UTC 跨日；统计「记录日均」分母是有记录的日期数。V4 趋势按天（周）、7天分组（月）、自然月（年）展示有记录日期的平均值，并支持四项营养切换；无记录分组为空值，避免被误读为摄入0。默认目标仅为可编辑初始设置。

## 结构

```text
src/domain/       类型、营养与日期/统计纯函数
src/data/         Dexie 数据库、记录/复制/备份事务
src/services/     本机 OCR 图片处理
src/components/   插画、滑动行、弹窗、表单、shadcn 风格 Button
src/pages/        首页、菜单、统计、我的
src/App.tsx       导航、弹窗状态与实时数据连接
public/           安装图标、原始 SVG、开源 OCR 组件及语言模型
```

数据库 `foodnote-v1`，schema version 2：`foods`、`entries`、`settings`、`metadata`（内置库导入标记）。JSON格式标识 `foodnote`，版本1。导入限制20MB，并验证ID、数值、日期、餐次、单位、配方及重复ID；验证和写入失败不会留下部分恢复数据。

## 尚未完成 / 使用边界

- **餐盘食物识别和营养估算尚未支持**：当前拍照识别包装营养成分表，不根据外观猜测重量、烹调油或食物营养；无在线AI服务、密钥或照片上传。
- 无云端同步、账号或跨设备自动同步，通过 JSON 备份迁移。IndexedDB 是当前浏览器/域名的数据，卸载、清理站点数据或系统回收可能删除数据，请定期备份。
- 自动化 WebKit 手机视口测试不能替代真实 iPhone 的安装、系统安全区和后台存储实机测试。HTTPS 部署后需实际设备验收。
- 为保持离线完整可用，图表库随应用缓存；初次加载需要联网。

实际执行结果记录在 `VALIDATION.md`。

## GitHub Pages 自动发布

推送到 `master` 后，`.github/workflows/pages.yml` 会运行营养与数据库测试、构建并发布。仓库 Settings → Pages 的 Source 选择 GitHub Actions。发布使用开源 `vite-plugin-pwa` 和 GitHub 官方 Pages Actions。

本地测试项目子路径：`BASE_PATH=/foodnote/ npm run build`。更换仓库名时，工作流会从 Pages 配置自动获取路径。饮食数据仅保存在访问设备的 IndexedDB 中，GitHub 只托管应用文件。不同网站地址的数据独立，需要用 JSON 备份迁移。

## 拍照与能量单位

首页「拍照识别营养标签」或菜单「＋」→「拍照识别营养标签」，选择拍照或相册图片。将营养成分表拍正、保持文字清晰，核对识别数字和能量单位，确认标签标注每100g、每100mL还是每份，然后创建食物。OCR 可能漏读或误读，所有结果须核对后保存。可展开识别文字，修正文字后重新解析。

`kcal = kJ / 4.184 = J / 4184`。例如836.8kJ自动换成200kcal。单位切换保持同一能量，不重复换算。每份数据先按标签重量归一化成每100单位；不能将 NRV% 当作含量。

照片只在设备中处理，识别用开源 Tesseract.js 6 和中英文模型，文件由本网站托管。首次识别需联网加载约13MB组件（依具体引擎而异），之后浏览器缓存仍存在时可离线识别。模型与核心通过按需缓存加载，不增加首次打开应用的下载量；浏览器清理缓存后需重新联网。`public/ocr/` 含上游来源和许可文件。尚未在真实 iPhone 摄像头上验收。

## 内置常用食物库（1.2）

79项常用食品，覆盖主食15项、肉蛋奶17项、豆类及豆制品5项、蔬菜16项、水果8项、坚果4项、调味料14项。数据直接提取自 USDA FoodData Central SR Legacy 2018-04 官方 CSV： https://fdc.nal.usda.gov/download-datasets/ 。每项保留 FDC 编号，详情页提供官方原始记录链接。原始描述和中文映射见 `references/common-food-sources.csv`；可用 `scripts/build-common-foods.py` 和官方 ZIP 重建数据。

全部按每100g可食部分录入，液体也按g，未擅自假设密度换成mL。生重、熟重、干重分开；即食产品和调味料使用“食用状态”。数值是所选 USDA 食物的参考均值，品种、品牌、做法不同可能不同，包装食品优先使用实际营养标签。米饭和水煮食材不包含额外烹调用油。食盐热量为0，但当前产品未记录钠，因此0热量不等于可以不限量食用。

打开新版时只添加一次，不覆盖已有同名、同单位、同重量基准食物，不创建饮食记录，也不改变目标。用户编辑、归档或删除后不会自动还原。导入使用事务和固定编号，多个标签打开不会重复导入；本机恢复备份不会再次填充已删除条目。旧版数据库升级保留已有数据。
